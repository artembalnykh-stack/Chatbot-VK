# VK-бот-консультант с GigaChat и базой знаний

Демонстрационный локальный бот для сообщества ВКонтакте: ищет ответы в локальной
базе знаний, передаёт найденные фрагменты и контекст диалога в GigaChat, показывает
сценарий сбора заявки с запросом согласия.

Рабочее окружение проекта — Python 3.9.6. Бот не требует белого IP и входящих
портов — используется VK Long Poll.

> **Демо, не готовое production-решение.** Личный кабинет и автоматическое
> удаление сохранённых заявок не реализованы; их можно добавить по отдельному
> запросу и согласованному ТЗ. Контекст сообщений хранится в памяти процесса
> и удаляется после 15 минут бездействия. Заявки остаются в локальном JSONL-файле
> до ручного удаления. Для запуска с реальными клиентами заказчику нужно отдельно
> согласовать обработку, доступ, сроки хранения и удаление данных; при необходимости
> привлечь юристов. Наличие запроса согласия в коде не является юридическим
> заключением или гарантией соответствия законодательству.

### Поток обработки сообщения

```
message_new
   ├─ вложение без текста?           → «понимаю только текст»
   ├─ /start, приветствие            → приветствие (без клавиатуры)
   ├─ активна заявка?                → шаги заявки (без ИИ и лимитов)
   ├─ «оператор» / «менеджер»        → старт демонстрационного сценария заявки
   ├─ лимит 1 запрос/минуту          → «подождите N сек.»
   ├─ мат                            → заглушка антимата
   ├─ prompt injection               → заглушка «отвечаю только по базе знаний»
   ├─ поиск по БЗ: ничего нет        → дисклеймер (без вызова GigaChat)
   └─ найдено                        → «печатает» → GigaChat строго по фрагментам
                                        └─ ошибка API → «сервис недоступен»
```

## 2. Быстрый старт на macOS

### 2.1. Python

Проект запускается в текущем рабочем окружении Python 3.9.6. Для установки
используйте Python 3.9 или новее:

```bash
brew install python@3.12          # если Homebrew уже есть
# либо установщик с https://www.python.org/downloads/macos/
python3 --version
```

### 2.2. Зависимости

```bash
cd bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> В этой папке уже может быть создано окружение `.venv` с установленными
> зависимостями — тогда достаточно `source .venv/bin/activate`.

### 2.3. Конфигурация

```bash
cp .env.example .env
open -e .env     # заполните токены, см. раздел 3
```

### 2.4. Проверка без сети и запуск

```bash
python main.py --check              # проверит .env и покажет статистику БЗ
python main.py --ask "сколько стоит лендинг"
python main.py                      # запуск бота
```

Команда `--check` проверяет наличие обязательных настроек и загрузку базы знаний,
но не проверяет действительность токенов и доступность внешних API.

Остановка — `Ctrl+C`. Логи пишутся в консоль и в `logs/bot.log` (ротация 5 МБ × 3),
все телефоны/e-mail в логах автоматически заменяются масками.

## 3. Получение доступов

### 3.1. VK

1. Создайте сообщество или откройте существующее.
2. **Управление → Сообщения → Настройки для бота**: включите сообщения сообщества
   и **Long Poll API** (версия API — 5.199 или новее).
3. **Управление → Работа с API → Ключи доступа → Создать ключ**:
   права `messages` (Сообщения сообщества) и `manage` (Управление сообществом).
   Это **ключ сообщества**, а не токен пользователя/приложения.
4. Скопируйте ключ в `VK_TOKEN`.
5. `VK_GROUP_ID` — числовой id сообщества **без минуса** (из URL или
   «Управление → Настройки → Адрес»).
6. Включите «Возможности ботов»: без этого не работают клавиатуры и статус
   «печатает». Клавиатуру бот не присылает — общение идёт обычным текстом.

Проверка токена:

```bash
curl "https://api.vk.com/method/groups.getById?group_id=ID&access_token=TOKEN&v=5.199"
```

### 3.2. GigaChat

1. Зарегистрируйтесь в GigaChat API (Studio/Sber) и получите **Authorization key**
   (строка `base64…`). Это не логин и не пароль.
2. Положите ключ в `GIGACHAT_CREDENTIALS`.
3. `GIGACHAT_SCOPE`: `GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_B2B` для юрлиц
   (зависит от тарифа и выданного доступа).
4. `GIGACHAT_MODEL`: `GigaChat-2` (базовая), `GigaChat-2-Pro`/`GigaChat-2-Max`
   или `GigaChat-3-Lightning`/`Pro`/`Ultra` — из списка, доступного вашему ключу
   (`GET /v1/models`). Устаревшие `GigaChat`, `GigaChat-Pro`, `GigaChat-Max`
   API больше не принимает (404 «No such model»).

**Про SSL.** По умолчанию `GIGACHAT_VERIFY_SSL=false`: GigaChat использует
сертификат НУЦ Минцифры, которого нет в стандартном хранилище macOS.
Для продакшена рекомендуется установить корневой сертификат НУЦ Минцифры и
выставить `GIGACHAT_VERIFY_SSL=true` (подробности — в документации GigaChat SDK).

### 3.3. Яндекс Таблицы (необязательно)

**Для текущего варианта эксплуатации Яндекс не нужен.** Оставьте
`YANDEX_TABLES_TOKEN` и `YANDEX_TABLES_ID` пустыми — интеграция «спит»:
её код не вызывается, заявки пишутся только в локальный бэкап
`var/leads_backup.jsonl` (права `0600`), уведомление приходит в VK.
В лог при старте пишется одна строка: «Яндекс Таблицы отключены…».

Если позже захотите дублировать заявки в таблицу, заполните переменные ниже —
код менять не нужно, канал включится автоматически.

1. Создайте таблицу (Яндекс 360 → Таблицы). В первой строке — заголовки:
   `Дата и время | user_id | Имя | Профиль | Контакт | Согласие`.
2. Получите OAuth-токен приложения с доступом к Таблицам:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`.
   Приложению нужны права на Яндекс 360 / Таблицы.
3. `YANDEX_TABLES_ID` — id таблицы из URL.
4. `YANDEX_TABLES_SHEET` — имя листа (по умолчанию `Leads`).
5. `YANDEX_TABLES_API_URL` — шаблон endpoint. Значение по умолчанию:
   `https://api.sheets.yandex.net/v1/spreadsheets/{spreadsheet_id}/values/{sheet}:append`
   (формат, совместимый с Google Sheets API: `valueInputOption=USER_ENTERED`,
   тело `{"values": [[...]]}`).

> **Важно:** API Яндекс Таблиц менялся между версиями и зависит от тарифа.
> Сверьте путь и формат с документацией вашего аккаунта. Менять код не нужно —
> достаточно переопределить `YANDEX_TABLES_API_URL`. Локальный бэкап пишется
> всегда, поэтому заявка не потеряется даже при недоступном API.

Проверить интеграцию можно локально: `python main.py` → нажмите «Связаться с
оператором», пройдите сценарий и посмотрите строку в таблице и в
`var/leads_backup.jsonl`.

### 3.4. Уведомления администратору

`ADMIN_VK_ID` — ваш личный VK id. Бот пришлёт уведомление о заявке **только с
масками** (`Ив***`, `+7 (XXX) XXX-XX-XX`, `vk.com/id***`).

Для варианта «только локально» `ADMIN_VK_ID` фактически обязателен: без него
уведомлений не будет вообще, и единственным местом с заявками останется файл
`var/leads_backup.jsonl`. Полные данные бот в VK не отправляет.

Последняя строка уведомления зависит от режима:

* Яндекс отключён → «Полные данные: локальный бэкап (var/leads_backup.jsonl).»;
* таблица включена и запись удалась → «Полные данные: Яндекс Таблицы.»;
* таблица включена, но запись не удалась → предупреждение о недоступности
  и отсылка к локальному бэкапу;
* не удалось ни то, ни другое → «свяжитесь с клиентом вручную».

## 5. База знаний

### 5.1. Форматы

* `.md`, `.txt` — абзацы; длинные абзацы режутся по предложениям (~900 символов).
* `.csv` — **первая строка обязана быть заголовком**, разделитель `,` `;` или таб.
  Каждая строка становится отдельным фрагментом вида `Колонка: значение; …`.
* Вложенные папки = темы. `knowledge_base/Услуги/чат-боты.md` → тема «Услуги».
* Файлы кодируются в UTF-8 (BOM допускается). Скрытые файлы/папки игнорируются.

### 5.2. Как добавить/изменить

1. Положите файл в `DATA_DIR` (или отредактируйте существующий).
2. **Перезапустите бота** — БЗ читается только при старте, горячей индексации нет.
3. Проверьте без запуска VK: `python main.py --ask "ваш вопрос"`.

Если ответ не находится, проверьте формулировки: поиск ищет по словам (с учётом
простых словоформ), поэтому в документах стоит использовать те же термины, что
и клиенты («лендинг», «карточки», «чат-бот», «цена», «оплата», «сроки»).

### 5.3. Почему нет векторной БД

По ТЗ нужен простой grep-подобный поиск без внешних сервисов. Эвристика:
совпадение ключевых слов (idf-взвешивание, префиксы словоформ) + штраф/бонус за
длину фрагмента (~450 символов — лучший) + близость к началу документа + бонус за
совпадение в названии темы/файла. Совпадения только в теме/заголовке весят вдвое
меньше, чем в тексте.

Дополнительно:
* **покрытие запроса** — фрагмент, где нашлось больше значимых слов вопроса,
  получает бонус; это отсекает ответы по одному общему слову;
* **точная фраза** — если слова запроса идут подряд (как в вопросах FAQ), фрагмент
  получает бонус, поэтому строка `Вопрос: …` обыгрывает общие статьи;
* строки CSV считаются самостоятельными записями, позиция внутри файла на них
  не влияет (иначе последние вопросы FAQ проигрывали бы первым).

Точки расширения помечены комментариями:
* `kb_search.KnowledgeBase._match` — сюда можно добавить синонимы или эмбеддинги;
* `kb_search.KnowledgeBase.load` — сюда — горячую перезагрузку по `mtime`.

### 5.4. Единая база знаний

Рабочая БЗ — `bot/knowledge_base/` (в `.env`: `DATA_DIR=./knowledge_base`).
Второй папки нет: прежняя `kb_bot/` перенесена сюда и удалена.

Структура тем: `О_студии`, `Услуги`, `Как_работаем`, `FAQ`, `Общение`, `Статьи`.
Цены продублированы в `Услуги/цены.csv`, частые вопросы — в `FAQ/faq.csv`.

Приветствие, подсказки и системный промпт уже написаны под AI-Мастерскую.
Если меняете тематику — правьте `GREETING`, `QUESTION_PROMPT` в `vk_handler.py`
и `SYSTEM_PROMPT` в `ai_adapter.py`.

## 6. Как работает диалог и ИИ

* В GigaChat уходят: системный промпт, последние сообщения пользователя и
  **только найденные фрагменты БЗ**.
* История — не более 5 сообщений на пользователя, в памяти процесса.
  Через 15 минут молчания контекст удаляется (фоновая задача каждую минуту).
* Если поиск ничего не нашёл, бот **не вызывает ИИ** и отдаёт ровно тот
  дисклеймер, который задаёт код. Это не даёт модели отвечать без найденных
  фрагментов в таком сценарии, но не гарантирует фактологическую точность
  остальных ответов.
* Ответ обрезается до 500 символов по границе предложения.
* Пока GigaChat готовит ответ, в диалоге виден статус «печатает»
  (`messages.setActivity`); он обновляется каждые 4 секунды и держится минимум
  секунду, чтобы не «мигал» при быстром ответе.
* При таймауте, 5xx, 429 или сетевой ошибке — «Сервис временно недоступен…»,
  ошибка пишется в лог.
* Один содержательный запрос на пользователя в минуту (`RATE_LIMIT_SECONDS`).
  Заявки и команды под лимит не попадают.

## 7. Технические меры и ограничения по данным

Реализовано:

1. **Явное согласие.** Перед сохранением заявки бот спрашивает разрешение на
   обработку ПД и сохраняет данные только после «Да». «Нет» — вежливый отказ,
   данные не пишутся.
2. **Минимизация.** Собираются только имя профиля, ссылка и контакт для связи.
   Больше ничего не запрашивается.
3. **Какие данные видит ИИ.** В запрос передаются вопрос пользователя, до пяти
   последних сообщений диалога и найденные фрагменты БЗ. Перед отправкой код
   пытается маскировать телефоны, e-mail и номера карт по регулярным выражениям.
   Имя, добровольно указанное в переписке, и произвольная ссылка не удаляются и
   могут попасть в GigaChat. Имя и ссылка на VK-профиль, которые бот получает
   отдельно для заявки, не добавляются в запрос к ИИ.
4. **Маскирование.** В логи и уведомления админу попадают только маски.
   `logging.Filter` дополнительно вычищает телефоны/e-mail из любых сообщений.
5. **Хранение.** Данные подтверждённых заявок сохраняются в локальном файле
   `bot/var/leads_backup.jsonl` (JSONL, права `0600`, создаётся автоматически).
   Автоматического удаления заявок нет; файл хранится до ручного удаления.
   Если Яндекс Таблицы включены, те же данные дублируются в таблицу.
6. **Идентификаторы.** В логах вместо `user_id` — псевдоним `u_<sha256>`.
7. **Prompt injection.** Жёсткие правила в системном промпте + проверка паттернов
   до вызова API.
8. **Антимат.** Встроенный список русских корней (с обходом leet-замен и повторов)
   + `better-profanity` для английского.

Это демонстрационный проект, а не сертифицированное или юридически проверенное
решение. Тестовые заявки в демо не относятся к реальным клиентам, однако бот
технически может получить профиль и контакты реального пользователя при запуске
с рабочими настройками. Перед таким использованием заказчику следует отдельно
определить обработку, доступ и сроки хранения данных в ТЗ; правовую оценку можно
проводить с юристами заказчика. Код сам по себе не подтверждает соответствие
152-ФЗ и не обеспечивает автоматическое удаление заявок.

## 8. Переход на продакшен: Long Poll → Callback API

### Почему локально Long Poll

Long Poll — исходящие HTTPS-запросы бота к VK. Не нужны белый IP, домен, HTTPS и
открытые порты, поэтому он идеален для запуска на ноутбуке. Минусы: бот должен
быть постоянно запущен, а при нескольких инстансах нужен один активный слушатель.

### Когда переходить на Callback API

При размещении на сервере: VK сам присылает события на ваш HTTPS-endpoint.
Плюсы: несколько воркеров, горизонтальное масштабирование, быстрый отклик,
меньше нагрузка на опрос. Требования: публичный HTTPS, домен, подтверждение
сервера, `secret` для проверки подлинности.

### Порядок перехода

1. Разместите бота на сервере в РФ, настройте домен и TLS (nginx/Caddy).
2. В сообществе: **Управление → Работа с API → Callback API**.
3. Укажите адрес `https://bot.example.com/vk`, скопируйте **строку подтверждения**
   и **секретный ключ**.
4. Поднимите HTTP-слой. Транспорт не влияет на бизнес-логику: `MessageProcessor`
   принимает тот же словарь события, что и Long Poll.

Минимальный вариант на FastAPI (установите `fastapi uvicorn`, они не входят в
`requirements.txt`, потому что локально не нужны):

```python
# callback_app.py — альтернативный транспорт вместо Long Poll
import asyncio
import hmac
import os
from contextlib import asynccontextmanager

from fastapi import FastAPI, Request, Response

from ai_adapter import AIAdapter
from kb_search import KnowledgeBase
from lead_collector import LeadCollector, LeadStorage
from utils import Settings, setup_logging
from vk_handler import MessageProcessor, VKClient
import aiohttp

settings = Settings.from_env()
setup_logging(settings)
queue: asyncio.Queue = asyncio.Queue()
CONFIRMATION = os.environ["VK_CONFIRMATION"]
SECRET = os.environ["VK_CALLBACK_SECRET"]

@asynccontextmanager
async def lifespan(app: FastAPI):
    session = aiohttp.ClientSession()
    vk = VKClient(settings.vk_token, settings.vk_api_version, session)
    kb = KnowledgeBase.load(settings.data_dir)
    ai = AIAdapter(settings)

    async def notify(text: str) -> None:
        if settings.admin_vk_id:
            await vk.send_message(settings.admin_vk_id, text)

    leads = LeadCollector(settings, LeadStorage(settings, session), notify)
    processor = MessageProcessor(settings, vk, kb, ai, leads)

    async def worker() -> None:
        while True:
            event = await queue.get()
            await processor.handle_event(event)   # та же логика, что в Long Poll

    task = asyncio.create_task(worker())
    yield
    task.cancel()
    await ai.close()
    await session.close()

app = FastAPI(lifespan=lifespan)

@app.post("/vk")
async def vk_callback(request: Request):
    payload = await request.json()
    if payload.get("type") == "confirmation":
        return Response(CONFIRMATION, media_type="text/plain")
    if not hmac.compare_digest(str(payload.get("secret", "")), SECRET):
        return Response("forbidden", status_code=403)
    # VK ждёт «ok» максимум ~3 секунды → тяжёлую работу отдаём воркеру
    await queue.put({"type": payload.get("type"), "object": payload.get("object", {})})
    return Response("ok", media_type="text/plain")
```

Запуск: `uvicorn callback_app:app --host 0.0.0.0 --port 8000`.

Важно: в Callback API включите событие `message_new`; для проверки подписи
используйте секретный ключ; не храните `VK_CONFIRMATION`/`VK_CALLBACK_SECRET` в
git. При нескольких воркерах понадобится общая очередь (Redis) — иначе события
разных процессов потеряют порядок диалога.

## 9. Решения и отличия от буквы ТЗ

* **FastAPI не используется локально** — выбран чистый `asyncio + aiohttp`, как
  разрешено в ТЗ: меньше зависимостей и один стек. FastAPI-пример выше — только
  для Callback API.
* **`pandas` не включён.** CSV читается стандартным `csv`, Яндекс Таблицы — по
  REST. Меньше зависимостей и меньше поверхность атаки; данные в pandas не
  нужны.
* **Дисклеймер при пустом поиске формируется кодом, а не моделью.** Это ровно
  фраза из системного промпта, но детерминированно: модель не может
  переформулировать её или что-то добавить.
* **Системный промпт адаптирован под AI-Мастерскую.** Структура правил 1–5 из
  ТЗ сохранена (только БЗ, дисклеймер, запрет выдумок, защита от инъекций,
  краткость), плюс правило 6 — запрет запрашивать/повторять ПД. Формулировки
  заменены с «магазина» на студию услуг.
* **Endpoint Яндекс Таблиц вынесен в конфиг.** API Таблиц отличается по версиям
  и тарифам; шаблон можно заменить без правки кода. Плюс всегда пишется
  локальный бэкап.
* **Клавиатура отключена по требованию заказчика.** Общение идёт обычным
  текстом: кнопки «Доставка/Оплата» убраны, команды «оператор» и «задать вопрос»
  работают как текст. Это отличие от исходного ТЗ, где клавиатура была
  обязательной.
* **История диалога** хранится в памяти процесса до 5 сообщений и очищается
  после 15 минут бездействия; перед отправкой отбрасывается ведущее сообщение
  ассистента, чтобы промпт начинался с вопроса пользователя.
* **Статус «печатает»** добавлен через `messages.setActivity`. Если API вернёт
  ошибку (например, у сообщества выключены «Возможности ботов»), бот просто
  отправит ответ без индикатора.

## 10. Диагностика

| Симптом | Что проверить |
|---|---|
| `Ошибка конфигурации: Не заданы ...` | заполнен ли `.env`, запущен ли из `bot/` |
| Бот молчит, в логе `Long Poll: ошибка` | ключ сообщества, включён Long Poll, `VK_GROUP_ID` без минуса |
| `[912]` в логе | включите «Возможности ботов» в настройках сообщества: без этого не работают клавиатуры и статус «печатает» |
| `[901]` в логе | пользователь запретил сообщения сообщества — это не ошибка бота |
| «Сервис временно недоступен» | `GIGACHAT_CREDENTIALS`, scope, лимиты, `GIGACHAT_VERIFY_SSL` |
| Ответы «нет точной информации» | `--ask "вопрос"`: если фрагменты не находятся — переформулируйте документы/добавьте синонимы |
| Заявки не в таблице | `YANDEX_TABLES_*`, права токена, путь API; смотрите `var/leads_backup.jsonl` |
| В логах нет текста вопроса | так и задумано: текст не логируется, только длины/псевдонимы |

Полезно: `python main.py --check` (конфиг + БЗ) и `python main.py --ask "..."`.

## 11. Что можно добавить дальше

* горячая перезагрузка БЗ по `mtime` (точка — `KnowledgeBase.load`);
* синонимы/эмбеддинги (точка — `KnowledgeBase._match`);
* хранение контекста в Redis для нескольких воркеров;
* экспорт заявок в CRM вместо Таблиц (точка — `LeadStorage._append_remote`);
* метрики (Prometheus) и healthcheck для сервера;
* тесты на `pytest` (автоматические тесты пока не добавлены; доступны команды
  `--check` и `--ask` для ручной проверки).
