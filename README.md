## 💡 Что решает этот бот

Малый бизнес и студии теряют клиентов, потому что не успевают отвечать в ВК. Этот бот закрывает три боли:

1. **Отвечает по базе знаний** — передаёт модели найденные фрагменты и просит отвечать по ним; если поиск ничего не находит, выдаёт фиксированный дисклеймер.
2. **Показывает сценарий заявки** — запрашивает контакт и согласие, после чего сохраняет тестовую заявку локально; при настройке доступно дублирование в Яндекс Таблицы.
3. **Работает локально** — Long Poll API, поэтому не нужны сервер, белый IP, домен и HTTPS. Запускается на ноутбуке или VPS за 5 минут.

Это демонстрационный проект, а не готовая production-система или юридическая гарантия соответствия требованиям к персональным данным.
Личный кабинет и автоматическое удаление заявок не входят в текущий объём; их можно реализовать отдельно, если это потребуется реальному заказчику.
Использование с реальными клиентами требует отдельного технического задания и оценки процесса обработки данных заказчиком, при необходимости — с его юристами.

## ✨ Ключевые возможности

### 🧠 Умное консультирование
- Поиск по локальной базе знаний; при отсутствии результатов бот не вызывает ИИ и отправляет фиксированный дисклеймер
- Живой диалог через **GigaChat** с историей из 5 сообщений на пользователя
- Статус «печатает» — бот выглядит естественно в диалоге
- Ответы до 500 символов — кратко и по делу

### 📋 Сбор заявок (лидогенерация)
- Команда «оператор» → пошаговый сбор контакта → запрос согласия → сохранение демонстрационной заявки
- Валидация телефона (3 попытки) и опция «написать в ВК»
- Уведомление администратору в личные сообщения
- Дублирование в **Яндекс Таблицы** (опционально) + локальный бэкап JSONL всегда

### 🔒 Реализованные защитные меры
- Перед отправкой вопроса в ИИ регулярные выражения маскируют некоторые телефоны, e-mail и номера карт; имя, которое пользователь сам написал в сообщении, может быть передано модели
- Имя и ссылка на VK-профиль, полученные для сценария заявки, используются в данных заявки и не добавляются в запрос к ИИ; если пользователь сам напишет их в сообщении, они могут попасть в контекст модели
- **Маскирование в логах** — `+7 (XXX) XXX-XX-XX`, `Ив***`, вместо `user_id` — псевдоним `u_<sha256>`
- **Антимат** — русские корни с обходом leet-замен (`хуууй` → мат) + `better-profanity` для английского
- **Защита от prompt injection** — паттерны «забудь инструкции», «system prompt», «jailbreak» блокируются до вызова API
- **Rate limiting** — не чаще 1 запроса в минуту на пользователя
- Файл заявок с правами `0600` (только владелец)

### ⚡ Техническое совершенство
- **Чистый asyncio + aiohttp** — минимум зависимостей, никаких лишних фреймворков
- **Graceful shutdown** — корректная остановка по Ctrl+C
- **Автоочистка** — контекст диалога и сессии сбора заявки в памяти удаляются после 15 минут неактивности; заявки в локальном файле автоматически не удаляются
- **DI без FastAPI** — локально не нужен веб-слой; пример Callback API для сервера дан в документации
- **CLI-инструменты** — `--check` (диагностика конфига) и `--ask "вопрос"` (тест поиска без ВК)

```
                                        │
        ┌───────────┬───────────┬───────┴────┬──────────┬──────────┐
        ▼           ▼           ▼            ▼          ▼          ▼
    /start      «оператор»   антимат     injection   лимит   содержательный
   приветствие   заявка-диал  (заглушка)  (заглушка)  1/мин      вопрос
                                        │
                    ┌───────────────────▼───────────────────┐
                    │   KnowledgeBase — поиск по файлам БЗ   │
                    │   (idf + стемминг + покрытие + фраза)  │
                    └───────────────────┬───────────────────┘
                                        │
                            ┌───────────┴───────────┐
                            ▼                       ▼
                     ничего не найдено       фрагменты БЗ
                     → дисклеймер            → «печатает»
                     (без вызова ИИ)         → GigaChat
                                             → ответ ≤500 симв.
```

### Поток данных

```
Пользователь ВК
    │
    ├─── вопрос ───────► GigaChat (текст вопроса после ограниченной маскировки + история + БЗ)
    │
    └─── «оператор» ──► LeadCollector
                            │
                            ├──► var/leads_backup.jsonl (полные ПД, права 0600)
                            ├──► Яндекс Таблицы (опционально)
                            └──► уведомления админу (ТОЛЬКО маски)
```

**Граница данных:** запрос к ИИ содержит текст вопроса, последние сообщения диалога и найденные фрагменты БЗ. Код маскирует некоторые форматы телефонов, e-mail и номеров карт, но не удаляет произвольные имена и ссылки, введённые в сообщении. Имя и ссылка профиля, полученные из VK отдельно для заявки, в запрос к ИИ не включаются. Это не является гарантией обезличивания.

## 🧰 Технологический стек

| Компонент | Технология | Почему |
|-----------|------------|--------|
| Язык | Python 3.9+ (локально проверен Python 3.9.6) | Асинхронность, зрелость экосистемы |
| VK API | aiohttp + Long Poll | Нет белого IP и входящих портов |
| LLM | GigaChat (Sber) | Внешний API для генерации ответов по найденным фрагментам |
| Поиск по БЗ | Собственный grep-поиск с эвристикой | Без векторных БД, Elasticsearch и внешних сервисов |
| Хранение заявок | JSONL + опционально Яндекс Таблицы | Надёжный локальный бэкап всегда |
| Антимат | better-profanity + русские корни | Понимает обходы через leet |

**Всего 4 зависимости:** `aiohttp`, `gigachat`, `better-profanity`, `python-dotenv`.

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
cd bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Настройка

```bash
cp .env.example .env
# Откройте .env и заполните токены (см. раздел «Получение доступов» в README)
```

Что нужно получить:
- **VK_TOKEN** — ключ доступа сообщества (Управление → Работа с API → Ключи доступа, права `messages` + `manage`)
- **VK_GROUP_ID** — числовой id сообщества без минуса
- **GIGACHAT_CREDENTIALS** — Authorization key из личного кабинета GigaChat API
- **ADMIN_VK_ID** — ваш личный VK id для уведомлений о заявках

### 3. Проверка и запуск

```bash
python main.py --check                          # диагностика конфига и БЗ
python main.py --ask "сколько стоит лендинг"    # тест поиска без ВК
python main.py                                  # запуск бота
```

`--check` проверяет наличие обязательных настроек и загрузку базы знаний, но не
проверяет действительность токенов и доступность API. Реальные токены в публичный
репозиторий не добавляйте.

Остановка — `Ctrl+C`. Логи пишутся в `logs/bot.log` с ротацией 5 МБ × 3, ПД автоматически маскируются.

## 📚 База знаний

Формат добавления прост до невозможного:

- **`.md`, `.txt`** — абзацы, длинные режутся по предложениям (~900 символов)
- **`.csv`** — первая строка заголовок, каждая строка — отдельный фрагмент `Колонка: значение; …`
- **Вложенные папки = темы** — `knowledge_base/Услуги/лендинги.md` → тема «Услуги»

После изменения файла — перезапустите бота. Горячей индексации нет (по ТЗ), но точка расширения помечена в `KnowledgeBase.load`.

### Как работает поиск

Никаких векторных БД и внешних сервисов — чистая эвристика:
- совпадение ключевых слов (idf-взвешивание, префиксное сопоставление словоформ)
- штраф/бонус за длину фрагмента (оптимум ~450 символов)
- близость к началу документа
- покрытие запроса (сколько значимых слов нашлось)
- бонус за точную фразу (FAQ-строки обыгрывают общие статьи)

## 🔐 Демо-режим и данные

Проект демонстрирует технический сценарий консультации и создания заявки. Примеры заявок в локальной рабочей копии — тестовые, не заявки реальных клиентов. При запуске с реальными пользователями бот технически получает VK-профиль и может сохранять контакт, поэтому такие данные следует считать персональными.

- Контекст диалога хранится только в памяти процесса и очищается после 15 минут бездействия; он не записывается в файл.
- Подтверждённые заявки сохраняются в локальный JSONL-файл с правами `0600`; автоматического срока удаления нет. Удаление заявок сейчас выполняется вручную.
- Запрос согласия в интерфейсе — часть демонстрационного сценария и сам по себе не подтверждает юридическую достаточность согласия или соответствие требованиям закона.
- Код маскирует некоторые форматы данных, но не гарантирует полного обнаружения или обезличивания персональной информации.
- При реальном внедрении заказчику нужно отдельно определить цели, состав данных, тексты согласий, доступ, хранение и удаление в техническом задании; правовую оценку можно провести с юристами заказчика.

Личный кабинет и автоматическое удаление заявок в демо не реализованы. Их разработка возможна по отдельному запросу и согласованному техническому заданию.

## 🔄 Путь к продакшену: Long Poll → Callback API

**Сейчас** — Long Poll: бот сам опрашивает VK через исходящий HTTPS. Идеально для запуска на ноутбуке без белого IP, домена и открытых портов.

**Когда вырастете** — Callback API: VK сам присылает события на ваш HTTPS-endpoint. Горизонтальное масштабирование, несколько воркеров, быстрый отклик.

В документации есть готовый пример HTTP-слоя на **FastAPI** (~40 строк), который принимает события и передаёт их тому же `MessageProcessor` — бизнес-логика не меняется.

## 🔐 Что нельзя публиковать

Правила `.gitignore` по умолчанию исключают из Git:

| Путь | Почему чувствительно |
|---|---|
| `bot/.env` | токены VK и GigaChat, id сообщества и администратора |
| `bot/var/leads_backup.jsonl` | полные персональные данные клиентов |
| `bot/logs/bot.log` | id пользователей, источники фрагментов, пути |
| `bot/.venv/` | локальное окружение |

Перед первым коммитом убедитесь:

```bash
git status --short          # в списке не должно быть .env, logs/, var/
```

Если `.env` или файл заявок **уже** попадали в историю git — удаления файла
недостаточно: токены нужно **перегенерировать**, а историю — очистить
(`git filter-repo`). Правила `.gitignore` не защищают от уже сделанных коммитов.
